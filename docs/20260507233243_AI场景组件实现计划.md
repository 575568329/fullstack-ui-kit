# fullstack-ui-kit AI 场景组件实现计划

## 1. 项目定位

`fullstack-ui-kit` 不做通用后台组件大全，只沉淀三类内容：

- AI 场景组件
- 项目里可复用的业务沉淀组件
- 前端疑难杂症的抽象组件

最终目标不是堆数量，而是让这些组件在 `D:\Study\Node.js-Study` 的面试内容里可讲、可举例、可复用。

## 2. 设计原则

1. 优先服务真实场景，不追求大而全。
2. 组件边界清晰，避免一个组件承担过多职责。
3. 能抽成共用状态模型的，优先抽象，不重复造轮子。
4. 统一演示页结构，保证每个组件都能通过“说明 + 示例 + 状态”被讲清楚。
5. 组件命名尽量表达业务语义，避免空泛的通用命名。

## 3. 分层规划

### 3.1 AI 对话类

这一层展示的是“用户输入 -> 模型思考 -> 流式输出 -> 最终回答”的完整链路。

建议组件：

- `ChatMessage`
- `StreamingText`
- `ThinkingIndicator`
- `PromptComposer`
- `ConversationList`
- `ConversationHistoryPanel`

### 3.2 RAG / 来源引用类

这一层展示的是“回答为什么这么说”，重点是可追溯性和证据链。

建议组件：

- `SourceCard`
- `CitationList`
- `RagScoreBadge`
- `ContextSnippet`
- `DocumentPreviewCard`

### 3.3 Agent / 流程展示类

这一层展示的是“模型不是只会回答，还会执行步骤和调用工具”。

建议组件：

- `StepTimeline`
- `ToolCallPanel`
- `ActionTrace`
- `StatusPill`
- `ExecutionLogPanel`

### 3.4 项目沉淀类

这一层是库里最容易和真实项目挂钩的内容，适合讲业务场景和抽象能力。

建议组件：

- `UploadPanel`
- `FileStatusList`
- `KnowledgeBaseCard`
- `ConversationHistoryPanel`
- `ErrorStatePanel`
- `RetryNotice`

### 3.5 前端疑难杂症类

这一层专门沉淀那些在真实项目里高频出现、但很难一次讲清楚的状态处理问题。

建议组件：

- `SseStreamViewer`
- `AbortableActionBar`
- `DebouncedSearchBox`
- `AsyncStateView`
- `EmptyLoadingErrorShell`
- `KeyboardTrapModal`

## 5. 组件功能说明

### 5.1 `ChatMessage`

展示单条对话消息，区分用户、助手、系统消息，支持时间戳、状态和内容样式。

### 5.2 `StreamingText`

展示流式输出中的文本变化，适合模拟打字中、逐步追加、结束态。

### 5.3 `ThinkingIndicator`

展示模型生成前或处理中状态，强调“正在思考”的反馈。

### 5.4 `PromptComposer`

承载 prompt 组织、输入、模板填充、快捷插入和发送前校验等能力。

### 5.5 `ConversationList`

展示会话列表，用于切换不同会话、查看摘要和更新时间。

### 5.6 `ConversationHistoryPanel`

展示历史会话与上下文回顾，适合按时间分组、折叠、定位历史消息。

### 5.7 `SourceCard`

展示单个检索来源，包括标题、摘要、评分、位置和标签。

### 5.8 `CitationList`

展示回答引用的来源集合，强调答案的可追溯性。

### 5.9 `RagScoreBadge`

展示相关度或命中评分的小型信息块，适合作为辅助标识。

### 5.10 `ContextSnippet`

展示从文档中截取的上下文片段，突出“模型实际看到了什么”。

### 5.11 `DocumentPreviewCard`

展示文档预览入口，用于把回答和文档来源建立关联。

### 5.12 `StepTimeline`

展示任务步骤时间线，适合 Agent 流程、工作流和阶段状态说明。

### 5.13 `ToolCallPanel`

展示工具调用细节，包括参数、执行结果、耗时和成功失败状态。

### 5.14 `ActionTrace`

展示动作追踪链路，用于说明某一步为什么发生、前后依赖是什么。

### 5.15 `StatusPill`

展示统一的状态标签，如成功、进行中、失败、排队、暂停等。

### 5.16 `ExecutionLogPanel`

展示执行日志，适合长任务、批处理、调试过程和可观测性场景。

### 5.17 `UploadPanel`

展示上传、解析、处理中、失败和重试入口，是典型的异步任务组件。

### 5.18 `FileStatusList`

展示批量文件及其状态，适合批量上传或批量处理任务。

### 5.19 `KnowledgeBaseCard`

展示知识库概览信息，如名称、条目数、更新时间和状态。

### 5.20 `ErrorStatePanel`

统一展示错误信息、错误原因、处理建议和恢复入口。

### 5.21 `RetryNotice`

展示重试提示、自动重试或手动重试入口，适合失败恢复链路。

### 5.22 `SseStreamViewer`

展示 SSE 流式事件内容，适合调试流式输出和事件驱动接口。

### 5.23 `AbortableActionBar`

展示可取消、可中止、可恢复的异步操作条，适合长任务操作。

### 5.24 `DebouncedSearchBox`

展示防抖搜索输入，适合搜索联想、筛选和请求节流。

### 5.25 `AsyncStateView`

统一管理加载、成功、失败、空数据等基础状态，作为页面级状态壳。

### 5.26 `EmptyLoadingErrorShell`

把空态、加载态和错误态统一收口到一个容器里，减少页面分支判断。

### 5.27 `KeyboardTrapModal`

用于处理弹窗焦点捕获和键盘可访问性问题，只在确实要讲复杂弹窗时保留。

## 6. 实施顺序

### 第一步：统一底座

先补状态模型、导出方式、示例页结构和视觉基线，保证后续组件一致。

### 第二步：补核心 AI 组件

优先完成 `StreamingText`、`ThinkingIndicator`、`PromptComposer`、`ConversationHistoryPanel`。

### 第三步：补来源与引用链路

完成 `SourceCard` 之外的 `CitationList`、`ContextSnippet`、`DocumentPreviewCard`。

### 第四步：补 Agent 与异步流程

完成 `StepTimeline`、`ToolCallPanel`、`ActionTrace`、`AsyncStateView`、`ErrorStatePanel`、`RetryNotice`。

### 第五步：补项目沉淀组件

完成 `UploadPanel`、`FileStatusList`、`KnowledgeBaseCard`，让库里有真实业务落点。

### 第六步：补前端疑难杂症抽象

完成 `SseStreamViewer`、`AbortableActionBar`、`EmptyLoadingErrorShell` 等难点组件。

### 第七步：补文档与面试话术

把每个组件的用途、边界、适用场景、可讲点整理清楚，方便在 `Node.js-Study` 里直接复用。

## 7. 验收标准

1. 每个核心组件都能在演示页独立展示。
2. 每个组件都有明确的使用场景说明。
3. 组件之间没有明显职责重叠。
4. 核心链路能完整覆盖 AI 对话、RAG 引用、Agent 执行、异步状态。
5. 组件说明足够支撑面试讲解，不只是视觉展示。

## 8. 备注

- 当前仓库优先服务面试内容沉淀，不追求通用组件广度。
- 组件命名可以在实现时再微调，但必须保留业务语义。
- 如果后续范围收缩，优先保留能讲清楚链路的组件，而不是零散的小装饰组件。
